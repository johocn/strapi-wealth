# 优美惠市集超市·每周预订反向营销 — 设计

日期：2026-09-28
场景：传统超市「先进货再卖货」→ 优美惠市集反向营销「先收集客户需求与信息，再按需进货」
页面：`https://v.joho.cn/#/pages/activity/promo?id=...`（复用现有活动页与海报能力）
文件：C 端 `e:\code\shao\`；运营端 `e:\code\basic\`

## 背景与目标

传统超市先囤货再等客，压库存、猜需求。优美惠市集要反过来：**先收客户信息与产品需求，再按需进货**，每周一期滚动运营。

本次**不改玩法、不动系统功能**，只交付一套可反复复用的运营物料：

1. 活动页配置模板（复用现有活动体系与模块，每周克隆一期）
2. 宣传文案包（3 固定 + 5 每期轮换）
3. 海报模板（复用 `promo_share`，新增 2 个可选元素）
4. 缺省图（品牌 + 品类图标网格，750×750）
5. 运营 SOP（每周 6 步）

每周节奏：**周四 24:00 预订截止 → 周五到店取货**，硬提示「不预订不配货」。

## 已确认的决策（不再讨论）

| # | 决策 |

| 6 | 缺省图＝品牌 + 品类图标网格（暖底 `#FDECE3` + 「优美惠市集·每周市集」+ 8 品类图标，750×750） |

## 1. 活动页：一期页面的 8 个模块顺序

沿用现有 `activity` 内容类型与 16 种模块，**不新增模块类型**。一期页面按下列顺序配置（`sortOrder` 1→8）：

| # | type | 内容要点 |
|---|---|---|
| 1 | `cover` | 头图＝缺省图；主标题「你想吃什么，我们进什么」；副标题「周四 24:00 预订截止·周五到店取货」 |
| 2 | `notice` | 红线提示：**不预订不配货**（常驻，不可关） |
| 3 | `images` | 本期征集说明图组（每期换图） |
| 4 | `custom` | 征集区说明（`config.title` + `config.html`）：「勾选你想要的品类，我们照单进货」 |
| 5 | `goods` | **开卖区**：已开售商品行（缩略图缺省时用缺省图） |
| 6 | `custom` | 开卖区底部「推荐位」一条：`config.title` + `config.mainPush`（主推话术） |
| 7 | `info` | 取货信息：时间轴、取货地点、联系方式 |
| 8 | `floatContact` | 悬浮联系入口（微信/电话/留言） |

模块 4/6 用 `custom` 而非 `purpose`：`promo-purpose.vue` 只渲染 `activity.purpose` 单一文本，放两个 `purpose` 会让「征集说明」和「推荐位话术」被迫同文；`custom` 的 `config.title`/`config.html`/`config.mainPush` 每模块独立可取，满足文案包「一期一填、互不覆盖」。

表单配置（站内 `formConfig`，字段类型全部为现有能力）：

| key | label | type | 必填 | 说明 |
|---|---|---|---|---|
| `categories` | 想要的品类 | `multi` | 是 | 8 项：蔬菜 / 水果 / 肉禽蛋 / 水产海鲜 / 粮油调味 / 乳品烘焙 / 零食饮料 / 日用百货 |
| `items` | 想吃的单品（选填） | `textarea` | 否 | 自由填写，一行一个 |
| `phone` | 手机号 | `phone` | 是 | 取货通知用 |

`categories` 为 `multi` 类型，选项直接在后台配置，不写死在前端。

## 3. 海报模板（`promo_share`，600×1050）

复用现有 `promo_share`，**新增 5 个可选 text 元素**（4 枚品类 chip + 1 条主推横条）；不填则整块不绘制（`drawText` 在 `resolvedContent` 为空时早退，连底色也不画，沿用现有可选变量语义）。

### 落库与代码同步

模板定义存在两处，必须同步，缺一即版式不一致：

- 运营端落库脚本：`e:\code\basic\scripts\seed-poster-templates.cjs`（`PROMO_SHARE`）
- C 端内置兜底：`e:\code\shao\utils\poster-templates.ts`（`BUILTIN_TEMPLATES.promo_share`）

渲染器（`e:\code\shao\utils\poster-renderer.ts`）**不改**：两个新元素都是普通 text 元素，走现有绘制链路；`image_fallback_*` 与 `main_image` 兜底绘制已具备，无需改。

### 降级方案（供复核时选择，默认不采用）

**零模板改动**：不加元素、不改坐标，把「品类」并入 `goods_1` 行文案（如 `品类：蔬菜·水果·肉禽蛋·水产海鲜`），把「主推」并入 `title`/`activity_venue`。代价：品类只能以纯文本呈现，视觉弱于 chips 带；好处：对已上线的既有 promo 海报零视觉影响。

## 5. 运营 SOP（每周 6 步）

| 步 | 时间 | 动作 |
|---|---|---|
| 1 | 周日 | 发海报（含二维码）+ 群分享话术，开启本期征集 |
| 2 | 周四 20:00 | 群里提醒「周四 24:00 预订截止·不预订不配货」 |
| 3 | 周四 24:00 | 截单，导出预订表单，按品类汇总后下单进货 |
| 4 | 周五早上 | 后台补填已到货清单（`goods` 模块）+ 发到货播报 |
| 5 | 周五 | 客户到店取货 |
| 6 | 周五晚 | 复制上一期 activity，替换每期轮换的 5 处文案与图，准备下一期 |

## 约束

- 不新增模块类型、不改活动/海报数据模型、不改渲染器绘制逻辑。
- 不改玩法、不动既有报名/发分链路。
- 新增元素全部可选，不填不绘制；对未使用新变量的历史活动页无功能影响。
- 遵循 shao 目录铁律：不升级 vue、不新增依赖。
- 缺省图作为静态资源随 C 端发布，放 `static/` 目录，不引入运行时请求。

## 风险点

- **版式位移**：`promo_share` 既有元素坐标上移，已上线的 promo 海报重新生成后版式变化（无新变量时也会变）。缓解：仅影响 `promo_share` 一个模板；如需零影响，改采「降级方案」。
- **两处模板不同步**：落库脚本与 C 端内置兜底必须逐值一致，否则线上/兜底版式不一致。验证时需同时比对。
- **chips 溢出**：4 枚 chip 等宽 126 是固定几何，品类名超过 4 字会折行/溢出，运营侧需约束品类短名（≤4 字）。

## 验收

1. 执行落库脚本后，后台 `promo_share` 元素数与坐标与本文档表格一致；`BUILTIN_TEMPLATES.promo_share` 逐值一致。
2. C 端打开 promo 页生成海报：`goods_category_1..4` 与 `main_push` 有值时正常绘制；全空时这两块不绘制且画布无留白异常、无溢出。
3. `main_image` 留空且传入 `image_fallback_*` 时，缺省绘制正常（回归现有能力，不倒退）。
4. 活动页一期配置 8 模块按顺序渲染；表单勾选品类 + 填单品 + 手机号可正常提交。
5. `poster-templates-promo-share.test.ts` 断言更新并通过；H5 构建通过。
